How it fits together

From votes to seats

Each model estimates first-preference votes in each district, then transfers preferences to work out who wins. Repeating this with different votes and preference flows gives a range of possible results. The share of simulations a candidate wins becomes their estimated win chance.

The count engine

A precise preferential count

We check the counting engine against official results. Future votes and preference flows still have to be estimated.

Checking past counts

Electoral commissions publish how votes transfer at each stage of a count. We construct groups of ballots that reproduce those published transfers and totals exactly. This checks the engine against official counts without claiming to recover voters’ original ballots.

How preferences decide a seat

Each district is counted by eliminating the lowest-polling candidate and distributing their ballots to the next continuing preference, one exclusion at a time.

Geography

Booth-to-district mapping

Federal polling places are assigned to state districts geometrically: a booth counts only if it sits inside the district and within 1 km of its own federal division.

Preferences

Fitted preference flows

Past preference counts help estimate where votes go when a candidate is eliminated. Forecast backtests use preference data from the previous election.

Uncertainty

Simulating possible elections

The Forecast Model varies statewide support, regional and local shifts, and preference flows. It counts all 88 districts in each simulation to estimate win chances and the range of possible seat totals.

The models

Two different questions

Forecast Model: past results and current polls

Starts with past state results and adjusts support to current polling. It uses the declared candidates and estimates how preferences decide the contest between the main contenders.

Read the methodology →

Baseline Model: federal ballot rerun

Every polling place’s votes from the most recent federal election are put into the state district it sits in, and each district’s preferential count is estimated assuming support stays the same. This gives us a simple comparison for judging whether the Forecast Model adds value.

Read the methodology →

Backtests

Benchmark results

We compare estimates for past elections with the official results. Each model’s page lists its completed tests.

Forecast backtests

These tests were produced after the elections. They show how the models perform using inputs available before voting. The Forecast Model uses the previous state result and preference flows, plus pre-election polls and candidates for the election being tested. The Baseline Model uses the preceding federal election.

The metrics

Seats right counts how often the favourite won. Brier score measures the error in the chances assigned to all candidates. Log loss measures how much chance the model gave the actual winner and heavily penalises confident mistakes.

Lower Brier scores and log loss are better. Both are zero for a perfect forecast. Unlike seats right, they distinguish between a losing favourite given a 55% chance and one given a 99% chance.

Reproduce the numbers

Every archived forecast ships a reproduce.sh that downloads the inputs (cached under data/) and reruns the models. Seed and settings are in each run’s run_metadata.json. AEC input files carry SHA-256 checksums in data/federal/*/manifest.json.

Step-by-step commands are in the repository README, Reproducing the results.

Independence charter

Non-partisanship & citation

Seat Projections is an independent civic data project. It accepts no donations, has no party affiliation and no advertising. Every number on this site is produced by open code from published electoral data, so any result can be recomputed and challenged.

Corrections and methodology questions are welcome via the repository’s issue tracker or email hello@seatprojections.au.
